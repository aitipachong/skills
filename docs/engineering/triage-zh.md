## 它的作用

`triage` 通过一个由分诊角色组成的小型**状态机**，推动你项目追踪器（issue tracker）中的 issue 流转——对它们进行分类、验证其描述、必要时通过追问把它们打磨成形，最后留下一份可直接交给 agent 的任务简报（brief）。

它从不会盲目打标签。每个被分诊的条目都恰好携带一个**类别**角色（`bug` / `enhancement`）和一个**状态**角色（`needs-triage`、`needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix`），并且它*只给出建议然后等待*——它会带着理由告诉你它的类别与状态判断，然后只在你指示后才行动。在把任何内容提升为 `ready-for-agent` 之前，它会先验证其描述：bug 会被实际复现，PR 会被检出并运行。

## 什么时候用它

你可以通过输入 `/triage` 并用自然语言描述你想要什么来调用它——agent 不会自己主动使用它。比如"给我看任何需要我关注的内容"、"我们看看 #42"、"把 #42 移到 ready-for-agent"。

当你的 issue 追踪器里堆满了原始的、未经评估的报告，而你希望把它们整理好、验证清楚，并转变成 agent 或人类可以接手的工作时，就该用它了。如果你想把一段已经沉淀下来的对话转变成一份新规格（spec），请使用 [to-spec](https://aihero.dev/skills-to-spec)；如果想把一份已有规格拆分成工单，请使用 [to-tickets](https://aihero.dev/skills-to-tickets)。`triage` 是相反的方向——它处理的是*已经*进入追踪器的内容。

## 前置条件

`triage` 需要读写你的 issue 追踪器，因此 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills) 必须先配置好追踪器以及标签映射。上面提到的角色名称是**规范名**——你追踪器中实际的标签字符串可能不同，而这种映射正是 setup 提供的。该配置还决定了外部 PR 是否算作一个请求入口，以及谁算外部人员。

## PR 就是一个附带代码的 issue

在追踪器把外部 pull request 视作请求入口的地方，`triage` 会用*同一台*状态机来处理它们：相同的类别角色、相同的状态、相同的流转——只是这些状态是针对 diff 而不是针对报告来判断的。`ready-for-agent` 意味着已附上一份简报，agent 应该接手对代码进行下一步处理；`ready-for-human` 意味着它已经准备好合并。自动发现（Discovery）只会浮现外部 PR，但被明确点名的 PR 无论作者是谁都会被分诊。

## 先验证，再写简报

把 `triage` 与临时贴标签区分开来的关键步骤是验证。它会按照报告者给出的步骤复现 bug，或者检出 PR 并运行测试，然后汇报结果：已确认（附带代码路径）、复现失败，或细节不足（这本身就是一个强烈的 `needs-info` 信号）。它还会做两项代码库检查——**冗余性**（这个功能是不是已经实现了？那就是 `wontfix`）和**既往否决**（`.out-of-scope/` 目录里是不是已经说过"不做"？）。一份经过确认的验证结果能让 agent 简报强得多；靠猜是不行的。

## 如何判断它工作正常

- 它触碰过的每个条目最终都恰好携带一个类别角色和一个状态角色——不会为零，也不会出现两个互相冲突的状态。
- 它会带着理由给你一份建议然后等待，而不是自己擅自改标签。
- 在任何内容到达 `ready-for-agent` 之前，bug 都被复现过、PR 都被运行过。
- 它发到追踪器上的每条评论都以 `> *This was generated by AI during triage.*` 免责声明开头。

## 它在流程中的位置

`triage` 是对你 issue 追踪器的一次**周期性维护**巡视——每当报告堆积起来时就运行它，让队列保持有序，让 `ready-for-agent` 这一栏值得信赖。它位于追踪器的最前端，处于构建链的上游：它写出的简报正是 [tdd](https://aihero.dev/skills-tdd) 之后拿去实现的东西。当一个请求需要打磨时，它会借助 [grilling](https://aihero.dev/skills-grilling) 和 [domain-modeling](https://aihero.dev/skills-domain-modeling)，一次一个问题地把它追问成形。它的近邻是 [to-spec](https://aihero.dev/skills-to-spec)——后者把一段新对话填充进追踪器，而 `triage` 处理的是已经在追踪器里的内容。当你不确定该用哪个 skill 或流程时，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你指路。
