## 它的作用

`prototype` 构建一个小型的一次性程序，它唯一的使命就是回答一个设计问题——这个状态模型用起来顺不顺手，或者这个 UI 到底该长什么样。

这份代码**从第一天起就是要扔掉的**，并且会被明确标记为如此。它没有测试，没有超出"能跑起来"所需的错误处理，没有抽象，也没有持久化。它的意义在于快速学到东西然后删掉——所以当你开始给它加固的那一刻起，你就已经不在做原型了。

## 什么时候用它

输入 `/prototype` 即可调用，或者当任务合适时 agent 会自动使用它。

当你有一个纸面上难以定夺的设计问题时，就该用它了——比如一个状态机，里面的各种情况你在脑子里装不下；或者一个页面，不看到几个并排的真实版本你就想象不出它的样子。如果是某个已经构建好的东西行为异常、你需要找出原因，请改用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)；原型探索的是"该构建什么"，而不是"已构建的东西为什么坏了"。

## 两个分支

问题决定形态，而形态只有两种：

- **"这段逻辑 / 状态模型用起来顺不顺？"**——一个迷你的交互式终端应用，把状态机推过各种棘手的情况，每次操作后打印出完整状态，让你能看到每一步发生了什么变化。
- **"这东西该长什么样？"**——在同一条路由上做出几个截然不同的 UI 变体，通过一个浮动工具条切换，这样你比较的是真实渲染出来的效果，而不是脑中的想象。

选错分支会浪费掉整个原型，所以要先弄清楚问题。两个分支都把状态放在内存里，用一条命令跑起来，并在每一步都展示完整状态。

## 把原型当作一手资料保留下来

一个完成的原型会留下两样东西。**答案**——结论加上它所解决的问题——是你需要持久记录下来的部分（写进 commit message、ADR 或 issue）。而**原型本身是一手资料**——是那个答案赖以得出的、可以运行的证据。

原型不属于主分支：没有测试，没有错误处理，没有任何值得维护的东西。但这不是销毁它的理由。答案被记录下来之后，把任何已验证的决策融入真实代码，然后把原型保存在一个一次性的分支上——游离于 main 之外、永不合并——并在实现 issue 上留一个指向它的上下文链接。主分支保持干净；原始的探索过程对任何想重新跑一遍的人来说也只需要点一下。一个烂在主分支里的原型早已失去了存在的意义——而一个作为一手资料保存在旁支上的原型没有。

## 它在流程中的位置

`prototype` 是一个随时可取用的独立 skill：你进入它来解决一个设计问题，然后退出来。它的答案往往会喂给下一步——一个已验证的状态模型或 UI 方向，会成为 [to-spec](https://aihero.dev/skills-to-spec) 落笔成文时的既定输入，或者成为一个值得通过 [domain-modeling](https://aihero.dev/skills-domain-modeling) 记录下来的架构决策。当你不确定该用哪个 skill 或流程时，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你指路。
