对 `src/` 下的代码做注释 **audit**：先量化 **coverage**，再补全缺漏。所有注释一律用中文书写。

`.json` 不在巡检范围：JSON 标准语法不支持注释，写了即为非法 JSON。

## 步骤

1. **扫描**——用 Glob 枚举 `src/**/*.{ts,tsx,js}`。完成标准：输出文件总数和完整文件清单，一个不漏。
2. **审计**——逐文件对照下方覆盖规则，记录每个缺漏项。文件超过 ~10 个时用 TodoWrite 逐文件跟踪。完成标准：清单中的**每个文件**都有结论（通过，或缺漏清单），每个类、接口、导出符号都单独判定过——不接受"大部分都有注释"。
3. **补全**——逐个消除缺漏项。完成标准：审计清单中每一项都已补上注释。
4. **复核**——重新扫一遍验证。完成标准：覆盖率报告达标——类和接口 100%，公共函数、方法、模块级变量与常量 100%。

## 覆盖规则

- **类、接口**：必须有块注释（TSDoc）。
- **公共函数、方法、模块级变量（含私有）与常量**：必须有块注释，coverage 100%。
- **复杂逻辑行内注释**：遇到以下任一情况必须加行内注释——嵌套循环 ≥2 层、条件分支 ≥3 个、异步/回调流程、非显而易见的边界值处理或算法步骤。
- **why-not-what**：行内注释回答读者心里的"为什么"——为什么用这个值、为什么这个顺序、为什么要判空。自测：如果删掉注释、读者单看代码就能推出同样信息，这条注释就是 What——删掉或改写为动机、约束或权衡。

## 文件类型专项规则

- 处理 `.tsx` 文件前，先读 [`TSX-RULES.md`](TSX-RULES.md)。
- 处理 `.js` 文件前，先读 [`JS-RULES.md`](JS-RULES.md)。
