## 它是做什么的

`writing-great-skills` 是你编写和修改 skills 时对照的参考——它是让每个 skill 行为可预期的共享词汇表与原则。

一个 skill 的职责是从随机系统中逼出确定性，所以目标不是每次运行得到相同的*输出*，而是相同的*过程*。**可预期性**是至上的美德，每一个设计决策都用它来评判——而不是用这个 skill 读起来有多聪明、多完整、多详尽来评判。

## 什么时候用它

这个 skill 需要你手动输入 `/writing-great-skills` 才会触发——智能体不会自己去调用它。

每当你在编写一个新 skill 或修改一个现有 skill，并希望它每次都以同样的方式运行时，就用它：决定调用方式、撰写描述、选择哪些内容放在 `SKILL.md` 里、哪些放进链接文件，或者诊断一个 skill 为什么跑偏了。

## 认知负荷

整份参考围绕的核心概念是**认知负荷**——以及它的对应物**上下文负荷**。每个 skill 都要消耗其中之一：

- 一个**模型调用**的 skill 每一轮都会在上下文窗口里占着一份描述，所以它消耗**上下文负荷**，但它会自己触发。
- 一个**用户调用**的 skill 剥掉了这份描述；它的上下文负荷为零，但现在*你*成了那个必须记住它存在的索引——这就是**认知负荷**。

这里的 skills 大多是用户调用的，这就是为什么认知负荷是整个系统致力于管理的压力：当用户调用的 skills 多到超出你脑容量时，解药是一个**路由 skill**，它列出其他 skills 的名字，以及各自该在什么时候取用。一旦你开始用这两种负荷来思考，大多数创作决策——拆还是不拆、内联还是渐进披露、模型调用还是用户调用——都变成了在不同地方做同一笔交易。

## 其他杠杆

参考的其余部分是把这些负荷花好的工具箱：

- **引导词**——模型预训练里已经存在的紧凑概念（_tight_、_red_、_tracer bullet_），智能体在运行 skill 时会用它思考。它用最少的 token 同时锚定执行*和*调用；要猎捕那些一个单词就能干掉的复述。
- **信息层级**——从 skill 内步骤，到 skill 内参考，再到藏在**上下文指针**后面的外部参考的阶梯。**渐进披露**就是顺着这架梯子往下走，让顶层保持清晰易读。
- **修剪**——单一事实来源、相关性，以及逐句应用的无操作测试，用来对抗**沉积**和**蔓延**。
- **失败模式**——**过早收工**、**重复**、**沉积**、**蔓延**、**无操作**——用来诊断一个行为异常的 skill。

## 它在整个流程中的位置

这是一个随时可取用的独立参考——是你在构建其余 skills 时随时查阅的元 skill，而不是链条中的一环。它天然的邻居是你维护的任何路由 skill，因为路由正是用户调用 skills 堆积起来的认知负荷的直接解药；当你不确定哪个 skill 或流程适合某项任务时，[ask-matt](https://aihero.dev/skills-ask-matt) 会在整套 skills 上为你指路。
